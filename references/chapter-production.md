# 章节生产

## 首章前确认门槛

生成第一章正式计划或正文前，读取 `novel-brief.md` 的确认记录。叙事视角、节奏与语言倾向、单章长度和内容边界必须是 `用户确认` 或 `用户授权 AI 决定`；如仍未决，每轮只询问其中最影响正文的 2–3 项并提供推荐。`AI 推荐待确认` 只能支持对话中的短预览，不能写入正式 `plan.md` 或正文。同人新故事同样适用：「写出来」和一句前提都不是故事线或节奏的确认。后续章节继承已确认设置，不重复询问，除非用户修改要求或当前章节需要明确例外。

## 章节计划合同

在 `plan.md` 中保持同一份合同，供写作、验收和修复共同消费。

使用拆书结论时，同时保留核心阅读承诺和本章的兑现证据：通过哪个选择、心理或关系后果形成目标体验，表层事件如何服务它。直接引用已确认合同即可，不新增一次确认；审校必须对照实际场景，不能只检查术语是否出现。作者纠正按 [写法合同](style-engine.md#接收作者纠正) 的范围落盘并回读。

### 基本任务

- 本章即时目标；
- 主要阻力；
- 参与角色及各自作用；
- 必须推进的剧情和信息；
- 必须保留的事实与优势；
- 必须触碰的伏笔或承诺；
- 必须发生的角色目标变化；
- 参与角色的当下呈现：本章可见身份、衣着/伤病/气色、可用物件、行为或声音锚点，以及不得误写的状态；
- 本章调用的世界规则、势力和舞台 ID，以及它们造成的准入、资源、信息或行动限制；
- 可以延后的事项；
- 禁止越过的边界。

### 读者体验

- 读者进入本章时最关心的问题；
- 本章可见回报及强度：`setup`、`partial` 或 `major`；
- 主角即时欲望；
- 关键转折；
- 情绪位移；
- 信息交付；
- 章末相对章初的净变化；
- 继承的旧钩子责任；
- 约定在哪个动作、画面或回应处收笔，读者由此带走什么期待。

### 本章有效写法

有本书已确认的 `writing-style.md` 时，按 [写法资产与表达合同](style-engine.md) 记录本章实际生效的正向写法与反模板化规则 ID、来源，以及与本章冲突而暂停的表达项。章节例外和本次用户要求只覆盖表达方式，不能改变上述任务与读者体验义务。没有写法资产时，沿用简报的叙事偏好与通用反模板化基线；不额外追问新手。

### 章节节奏段与篇幅预算

每份 `plan.md` 都必须写入一份可执行的篇幅合同；没有用户特别指定时，继承 `novel-brief.md` 的书级默认值。字数统计使用**正文汉字/字符数，不含标题、Markdown 标记和审查记录**；它是创作预算，不要求机械凑到精确数字。

- 目标字数：例如 `3000`；
- 可接受区间：例如 `2500–3500`；
- 预算来源：书级默认 / 用户固定 / 本章经批准的例外；
- 本章为何需要该长度：追逐、审讯、情绪转折、信息揭示或多线交叉等；
- 最低有效内容包括接近篇幅下限时仍要兑现的事件、回报、转折和约定的收尾。
- 超出上限时优先删减的内容：回顾、重复解释、同义情绪、无后果的环境描写；
- 未达下限时只能补入的新内容类型：新的有效行动、阻力、选择、对话冲突、可验证信息或关系变化。

分配篇幅前，先用几句话讲一遍这场戏。若读者已经猜到结果，此刻仍会惦记谁的选择、一个愿望要付出什么，或原先相信的事会怎样改变？把支撑这份期待的举动或发现写进已有的节奏段。若几段都只是重复处境，合并它们，把篇幅留给真正影响后文的事。

按这章实际需要安排场景和节奏段，尊重作者指定的结构。一次谈话可以撑起整章，几个地点也可以共同交付一个转折。用场景预算说明篇幅花在哪里，各段合计应接近目标。下面以审讯章为例。

```markdown
## 章节节奏段与篇幅预算

- 目标字数：3000
- 可接受区间：2500–3500
- 预算来源：书级默认；本章无覆盖
- 本章长度理由：一次审讯、一次现场查验与一次章末反转，需要完整呈现对峙和证据链。
- 低于下限仍必须完成：A、B、C
- 超长时先删：重复回顾、第二轮无新信息的争执

| 节奏段 | 进入状态 → 动作与阻力 → 转折 | 读者回报/情绪 | 预算 | 离场状态 |
| --- | --- | --- | ---: | --- |
| 开篇抓手 | 旧钩子压迫主角行动 | 紧张、明确问题 | 600–800 | 主角必须作出选择 |
| 升级转折 | 阻力加码并交付新信息 | 局面或关系反转 | 1000–1300 | 原计划失效或升级 |
| 回报与牵引 | 兑现部分承诺，留下新压力 | 可见回报与追读欲 | 700–1000 | 明确净变化和下一章问题 |
```

## 写作上下文优先级

按优先级读取：

1. 本章计划与义务合同；
2. 上一章实际尾段；
3. 角色硬事实与参与角色的当下呈现；
4. 禁止越界与受保护揭示；
5. 当前卷窗口和节奏段职责；
6. 当前场景涉及的世界规则、势力状态和舞台限制；
7. 相关未兑现承诺和资源状态；
8. 风格合约和参考写法。

摘要不能替代上一章实际尾段；软性角色简介不能替代角色硬事实。

## 上下文清单

连续性已启用时，在 `chapters/chapter-XXX/context-package.md` 中为本章建立简明清单。它只记录：

- 本章目标、稳定正文来源与当前卷窗口；
- 已选权威文件和每个文件的用途；
- 必需约束（事实、角色身份与当下呈现、禁止越界、直接钩子、资源风险，以及实际调用的世界条目 ID 和限制）；
- 因无关、重复或超出窗口而裁掉的内容；
- 缺失的硬约束与保守处理方式。
- 本章有效写法的来源、规则 ID 与例外；不复制样文、拆书原文或整张资产卡。

清单是本章的约束装配包：角色、世界和连续性模块仍是长期事实的权威源。清单不能复制大段正文、完整角色档案或整本设定，也不能在此单独改写长期事实；应记录稳定 ID 和来源路径。缺失硬约束时，不编造历史；缩小本章行动或把风险列入审查。

`novelctl context` 装配的资料供核实来源。组织写章任务时，只展开本场用得上的事实。写明视角人物亲历了什么、能据此试什么。尚未揭示的真相和禁止越界的事项继续约束写作，避免让人物在心声里逐项否认自己不可能想到的事。分镜交代选择和后果，具体措辞与动作细节留给写手，作者指定的原句照办。

## 试读一场戏

作者说“试写一版我看看”，直接进入这场戏。若已给分镜、样稿或指定末句，复用它们。需要组织输入时，挑出本场会改变判断的事实：视角人物此刻能看到什么、谁要做什么、哪个动作使别人改变主意、约定在哪儿收笔。按戏的需要取舍，无需让作者填表，也无需先展示执行单。

例如，哥哥正要在合格凭单上落印，陆昊让他多验一次，两块军晶只有一块出现裂纹。哥哥肯封存时，匠人才说已有一箱出库。作者指定最后一句是“谁领了货？”，这一版就交到这个问句。焦虑怎样表现、要不要穿插笑话，交给本场的人物与语气决定。

没有要求落盘时在对话中给稿。明确“单独存一份”时在作品的创作记录目录另存候选，沿用该书命名习惯。续写新段时接上一版实际末句，沿用原交付方式，并为新增候选另取文件名。试读与比较不启动正式章节步骤、不登记连续性。作者明确选定后再转正式。若请求还明确限定篇幅、视角或最后一句，交付前对照实际文本；只修失守的位置。

## 正文生成

先使用本章有效写法组织叙述距离、角色声音、场景细节和段落节奏，并在初稿阶段避免成簇的模板化表达；不要等二稿才补救语言。写法与情节事实或当前章任务冲突时，以事实和任务为准。

从能让读者在意这场戏的位置开场。一个人的选择能带动后文，旁人的误会、一处反常的景象或一句迟迟等不到的回答也可以。心理活动用人物此刻会想到的词，给动作、停顿和余味留出空间。

按本章承诺写出局面、认识或关系发生的变化。受篇幅限制时优先保留造成变化的过程，压缩重复体感与旁白解释。已经约定最后一笔的，写到那里收住。等待回应、一个成立的结果或安静后的余味都能承接下章。

默认一次生成整章，保持声音、因果和情绪连续。场景卡用于规划、诊断和局部修复，不要默认按场景多轮拼接正文。

## 多子代理模式已暂停

即使用户要求连续多章、提速、并行或子代理，也不要启动子代理、滚动预热或候选交接。按“计划与上下文 → 整章正文 → 人味化与审查 → 主代理回灌”完成当前章后，才读取新稳定资产开始下一章。历史并行实验资料不属于当前生产流程。

## 中文小说反模板化二稿

完整正文生成后，默认进行一次受约束的二稿。先读取 [chinese-novel-humanization.md](chinese-novel-humanization.md) 与本章有效写法，再执行：

1. 锁定章节合同、已发生事实、信息边界、角色关系、物件归属和章末钩子。
2. 对照本章写法合同找出有正文证据、成簇出现的模板化表达或人物声音偏差，而不是逐词清洗；没有实质问题的段落保留原样。
3. 以场景中的动作、误解、具体物件、人物偏见和未说尽的话替换解释性旁白；允许段落长度与情绪节奏自然变化。
4. 重新检查本章必须发生事件、禁止越界和净变化。

二稿可以重组段落和句子，不必保留初稿段落数。不得用错别字、病句、随机无关细节、隐藏字符、伪造作者经历或篡改人物事实制造“人味”。当用户要求对照实验时，保留初稿并将二稿写入独立文件；未经确认不得覆盖用户编辑的正文。

若用户提供外部检测结果，先读取 [chinese-novel-humanization.md](chinese-novel-humanization.md) 的“外部检测器的有效性边界”。工具未通过与任务相关的对照验证前，不得用其分数触发重写、停损或作者参与流程；作者参与仅由作者对个人创作边界的需求触发。

## 接收判断

先判断：

- 是否存在可读正文；
- 是否完成 must-hit 义务；
- 是否越过 forbidden crossing；
- 主角是否主动；
- promised reward、key turn 和 net change 是否可感知；
- 是否承接上一章；
- 是否出现硬事实冲突；
- 是否处于篇幅合同的可接受区间；若不在区间，是否有明确且可接受的剧情原因，以及是否出现凑字数或仓促收束；
- 读者开始在等什么，哪一处使这份期待发生变化，结尾是否兑现了约定的回报并停在约定处；
- 是否有明显占位符、AI 自述、重复、截断或工程词泄漏。
- 是否存在成簇的模板化叙事：过密否定式并列、格言化总结、每段都刻意收束、平均化短段、解释代替场景、角色口吻趋同。
- 本章有效写法是否产生预期读感；若偏离，指出规则 ID、正文证据与影响，并按规则权限决定提醒或定点修文。

不要将外部检测器的百分比当作来源证明或唯一验收标准。将其作为可记录的观察值，仍以章节合同、可读性、人物辨识度、连续性和用户的创作选择为主。

把缺失义务区分为：

- `patchable_obligation_gap`：局部补写即可；
- `rewrite_needed`：整章组织需要调整；
- `plan_misalignment`：本章职责与邻章安排失配。

篇幅偏差本身不是自动重写理由。正文过短但本章义务缺失，按缺失义务处理；正文过长且存在重复或无效段落，优先局部删改；正文已完成合同且偏差来自用户确认的风格选择，可记录为 `continue_with_warning` 而非强行改写。

## 稳定后更新

正文稳定后再更新：章节摘要、已发生事实、角色状态、资源变化、关系变化、信息边界、伏笔推进，以及已经在正文中明确发生的世界状态变化。不要在正文仍处于修复时提前写入这些资产。

稳定的含义是：审查为 `accepted`，或为 `continue_with_warning` 且正文仍可作为下一章的事实来源。此时按以下顺序执行：

1. 记录 `continuity/chapter-deltas/chapter-XXX.md`，并标明最终正文来源与指纹。
2. 更新事实、伏笔和资源账本；个人资源、知情边界与直接关系同时回写相关角色档案和必要的角色矩阵。若正文明确改变势力控制、舞台准入、公共秩序或规则的已知例外，在 `world-bible.md` 的“当前世界状态”中追加带章节证据的状态项；不得把角色猜测、计划事件或未证实传闻写成世界事实。
3. 将可继续的局部问题写入 `production/quality-debt.md`；不得把它们伪装成已修复。
4. 更新 `production/recovery.md` 与 `novel-state.yaml` 的最后已提交章节和唯一下一步。

`local_patch_plan`、`rewrite_needed` 与 `stop_for_replan` 不是稳定结果。它们不得产生稳定事实、资源变更或伏笔兑现记录。
