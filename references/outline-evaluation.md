# 网文大纲评判 v1

这套评判回答三个编辑问题。读者会为什么点开这本书？第一次得到想看的东西以后，还有什么值得等？到下一卷时，前面的选择还算数吗？评判对象是当前工作区的书级规划和指定卷的规划。默认抽第一卷。评判结论描述大纲已经安排的阅读体验，真实追读率需要连载数据验证。

## 七个维度

开评前，从简报确认目标读者、题材承诺和作者已经锁定的边界。同一维度按本书承诺取证。悬疑可以用排除一种解释来兑现，感情线可以用一方终于愿意托付来兑现，经营文可以用第一位客人愿意再来兑现。

| 维度 | 在规划里追问 | 1 分 | 3 分 | 5 分 | 优先回哪里修 |
| --- | --- | --- | --- | --- | --- |
| 卖点与读者承诺 | 读者最想看谁在什么处境下做成什么？换掉本书的关键设定，哪段乐趣也会消失？ | 只有题材标签，摘掉书名就认不出故事 | 能说出向谁提供什么乐趣，卷目标仍可套在许多书上 | 一句话能预期本书特有的选择，简报和卷目标都安排了能看见的结果 | 新书简报、故事主线 |
| 开篇牵引与首次兑现 | 读者先替谁着急？本卷开局哪次行动给了第一个答案，又留下什么可等？ | 连续介绍背景，人物当下无事可做 | 有明确问题或强刺激，首个回报和主卖点连接较弱 | 起始压力逼出选择，早段给出与承诺同类的回报，其后果引出下一步 | 开篇细纲、卷内前段 |
| 故事发动机与冲突升级 | 连看两轮，第一轮所得或所失，怎样迫使人物换一种做法？ | 每轮靠巧合开新任务，换序也说得通 | 第一轮因果成立，第二轮只把对手或规模放大 | 前一轮改变信息、能力、利益或信任，让旧办法遇到新阻力，下一轮有新的解法和代价 | 故事主线、卷骨架 |
| 人物选择与关系变化 | 谁本可以选另一边？一个有自己目标的人拒绝、支持或改约后，谁不得不改计划？ | 配角只送线索，关键结果由外人安排 | 有动机和选择，关系变化主要由大纲宣告 | 两方各有可理解的选择，一方的决定改变另一方的行动，后续节点还承受这次选择的得失 | 人物档案、关键转折 |
| 世界规则与代价 | 哪条能力、职业、制度或日常条件关掉了最方便的解法？人物用什么换来结果？ | 靠临时例外解决核心困难，既定限制随时消失 | 规则清楚，偶有代价，后续选择很少受影响 | 同一规则既给机会也限制行动，代价在后来一次关键选择中仍然有效 | 世界设定、资源约束、卷骨架 |
| 期待管理与阶段回报 | 沿一条读者在意的问题，能否指到提出、中途进展、阶段答案？在等的途中读者得到了什么？ | 反复预告同一个答案，阶段结束也没有进展 | 有铺垫和结算，中段有一段只在等待，或连续重复同一种回报 | 读者能逐段修正预期，小答案本身值得等，大答案来时能认出前面的准备 | 节奏表、逐章细纲、伏笔安排 |
| 分卷递进与终局 | 卷末谁获得或失去什么，使下一卷有必要发生？首卷许下的愿望最终怎样得到回答？ | 换地图就清零，末卷目标与开书愿望脱节 | 各卷有目标，某个卷间交接靠另派任务，或终局只写胜利 | 卷末得失成为下卷起点，终局方向回应核心愿望并保留代价。单卷看阶段到结尾的承接 | 分卷规划、故事结局 |

2、4 分用于相邻两档之间，并说明相差的那一步。评第 2 卷以后，“开篇”指指定卷的开局。远期软规划只按作者承诺的方向判断，已有卷末方向就可以检验因果，不要求先写远期逐章细纲。

区分“材料不足”和“设计薄弱”。只有一份简报，找不到等待如何兑现，可以留空并写明需要哪段卷纲。卷纲已经排到结尾，提出的问题一直原地踏步，则可引用提问和最后一次重复的位置给低分。慢热、群像、日常都可以有阶段回报。一次坦白、一条被推翻的嫌疑、一次敢于托付，都可能足以改变局面。

## 一次评判怎样完成

在仓库根目录或已安装的 Skill 根目录执行命令。`workspace` 传目标书目录。下例把表和结果放在本次评判目录，文件名可以按作品习惯调整。

```sh
python scripts/novelctl.py outline-review "$workspace" --volume 1 --output "$run/评判表.json"
# Codex 读取表中列出的规划并完成下述判断，保存一份填写后的 判读.json。
python scripts/novelctl.py outline-review "$workspace" --volume 1 --review "$run/判读.json" --output "$run/评判结果.json"
```

1. **确定读的是哪一版。** Python 从中文或英文作品状态取登记路径。材料包括书级简报、主线、世界与人物、分卷规划，以及该卷登记的卷纲、节奏表、开篇和逐章细纲。可定位卷归属的正式章计划也可佐证。未登记或缺失的资料保留为缺口。已登记为 ready 的文件如有手改，清单以 `working_copy` 和两份指纹标出，本轮评的是磁盘上的工作稿。待更新、阻塞或还在写的文件不作得分证据。
2. **由 Codex 完成判读。** 按目标读者的口味，逐项给 `score`、`reason`、`evidence` 和 `next_step`。每条证据含清单里的 `source`、原文件从 1 起算的 `line` 和该行的短引文 `quote`。跨轮因果、关系改变、铺垫回收宜各引前后两处，并解释中间怎么连起来。材料不足时用 `null`，写清缺什么和去哪补。3 分及以下给出能交给具体规划环节的最小改动。若同一问题影响两项，指明首要修订位置。
3. **核对结果并交付。** Python 重读当前取材版本、核实引文和分值，给出七项覆盖数、待补证项和优先修订项。七项都能评分时才算等权均分。回复先给值得保留的一处设计、影响追读最大的缺口及卷章位置。只要对话结论时可用临时目录，要求留档时在作品创作记录下新建本轮目录。指定 `--output` 只新建文件，省略时输出到终端。

用于后续自动优化时，先保存原规划的评判记录作为基线。按同一题材、卷段、读者承诺和量表复评一次只改一处的候选稿。给评判者相同的任务说明，隐去版本优劣预期、旧分数和规划者的自评。填写 `judge.model` 的实际型号，宿主未提供时留 `null`。`judge.context` 用 `shared`、`separate` 或 `unknown` 如实记录评判与规划是否共用对话。换量表或裁判后重新评基线。分数提高时，还须指出哪段安排改善了哪种读者体验，才有采纳依据。

例如，一部渡口经营文写“生意越来越好”，只能说明作者的意图。如果卷纲写到女船主为等接生婆错过头班，赶集客退票，几位河西人却第一次把夜里求医的船钱交给她，就有了可查的取舍。下一段若让她在集市班船与夜航承诺之间排班，便补上了第二轮冲突。若只写“邻镇又开了一家更大的船行”，优先改的是故事发动机。这个判断可以在开写前做出。

## 职责与交接

- **拆书分析**提供有出处的机制、适用条件和反例。参考书说明一种设计怎样起效，分数取自目标作品自己的安排。
- **原创规划**维护简报、主线、人物、世界与卷章计划。评判由 Codex 以编辑视角独立读本版材料，先交证据和建议。作者选定或已有委托后，规划环节负责修改，回到受影响的卷章复评。
- **确定性脚本**管理本次材料指纹、引文定位、评分完整性与汇总。题材取舍、作品吸引力和缺陷成因由 Codex 判断。
- **跨项目交付**由 `autocommand` 记录采用版和范围。`assistant` 负责 Web 绑定后的正式章节生成、保存、审校和修文。若卷纲已安排回报，但成稿读不到它，交接时附该处规划和 Web 绑定修订，转章节侧追查。
